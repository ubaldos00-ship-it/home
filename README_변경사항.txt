2) 목록 번호 = 「보이는 개수」와 항상 일치 (22개면 최대 22번)
════════════════════════════════════════
  원인(왜 22개인데 23번이 나왔나)
    - 번호는 「고정 ID」가 아니라, 저장 순서상 「위치」입니다.
      삭제하면 남은 자료가 다시 1·2·3…으로 번호가 다시 매겨집니다(정상).
    - 그런데 번호를 「전체 목록」 기준으로 매기고 있어서,
      조회 필터(시도·시군구·읍면동·작물)가 하나라도 걸려 1건이 숨겨지면
      「보이는 건 22개인데 번호는 전체(23) 기준」이라 23번이 나왔습니다.
      (= 조회 필터가 걸려 1건이 안 보였던 것. 자료가 사라진 건 아닙니다.)
  수정
    - 번호를 「실제 보이는 목록(조회 필터 적용 후)」 기준으로 매깁니다.
      → 보이는 개수와 번호가 항상 일치합니다(22개면 1~22번).
    - 정렬(최근순·작물별·목록순서 등)을 바꿔도 각 자료의 번호는 그대로 유지되고,
      삭제할 때만 1~N으로 다시 매겨집니다.
  ※ 참고: 전체(조회 필터 「전체」)로 보면 숨겨졌던 그 1건까지 다 보입니다.
     만약 필터를 모두 「전체」로 뒀는데도 개수가 안 맞으면 알려주세요(점검하겠습니다).

검증 (브라우저 실제 테스트)
  - 필터 없음: 3건 → 번호 3·2·1 (최대 3 = 개수).
  - 특정 시도만 필터: 1건 → 번호 1 (이전엔 전체기준 3번이 나왔음).
  - 항목 줄바꿈 표시(라벨/주소/이름·전화·메모/날짜) 확인.
  - 실측(tonghab)·청취(chungchi) 동일 적용.
  - JS 문법 검사 통과(tonghab 22 · chungchi 13 인라인 스크립트).
